1. SYSTEM OVERVIEW
================================================================================

This system provides a REST API for medical image management using MongoDB as
the storage backend. Images are stored as Base64-encoded strings in MongoDB
documents along with their metadata.

CORE FUNCTIONALITY:
-------------------
1. Automatic image seeding from local inventory to MongoDB on first startup
2. Single API endpoint to filter and retrieve complete image documents
3. Base64 encoding for database-friendly image storage
4. Search by medical speciality and disease area
5. Full MongoDB document return including base64 data and ObjectId

KEY COMPONENTS:
---------------
- ImageService: Core service handling seeding, loading, and filtering
- MongoDB: Database storing images as base64 strings with metadata
- FastAPI: REST API framework
- Pydantic: Data validation and schema definition

TECHNOLOGY STACK:
-----------------
- Python 3.14
- FastAPI 0.124.1
- MongoDB (PyMongo 4.6.0)
- Pydantic 2.5.0
- Base64 encoding (Python standard library)

DATABASE:
---------
- Database Name: epocrates
- Collection Name: images
- Total Images: 24 (one missing from source inventory)
- Average Image Size: ~66 KB per image (~89,916 chars base64)
- Total Storage: ~2.3 MB

3. IMAGE SEEDING PROCESS (MongoDB Upload)
================================================================================

WHEN IT RUNS:
-------------
- Automatically on application startup
- Only if MongoDB collection is empty (count_documents == 0)
- Skips if images already exist (prevents duplicate uploads)

SOURCE DATA:
------------
Location: backend/imglibrary/
Files:
  - imglibrary.json (metadata: id, filename, speciality, disease_area)
  - imglibrary/*.jpg, *.png (actual image files)

STEP-BY-STEP PROCESS:
----------------------

Step 1: Check Collection
------------------------
Code: self.collection.count_documents({})
- Query MongoDB to count existing documents
- If count > 0: STOP (images already seeded)
- If count == 0: CONTINUE to seeding

Step 2: Load Metadata JSON
---------------------------
File: backend/imglibrary.json
Code: 
  json_path = Path(__file__).parent.parent.parent / "imglibrary.json"
  with open(json_path, "r", encoding="utf-8") as f:
      raw_images = json.load(f)

Result: List of 25 image metadata objects
Example:
  {
    "id": "001",
    "filename": "001.jpg",
    "speciality": "oncologist",
    "disease_area": ["cancer", "tumor"]
  }

Step 3: Process Each Image
---------------------------
For each metadata entry:

  3.1: Build Image File Path
  ---------------------------
  Code: img_path = images_dir / img["filename"]
  Example: backend/imglibrary/001.jpg

  3.2: Check File Exists
  ----------------------
  Code: if not img_path.exists(): continue
  Action: Skip missing files (doesn't crash)

  3.3: Read Binary Data
  ---------------------
  Code: image_bytes = img_path.read_bytes()
  Result: Raw binary image data (bytes object)
  Example size: 45,234 bytes for a typical image

  3.4: Encode to Base64
  ---------------------
  Code: image_b64 = base64.b64encode(image_bytes).decode("utf-8")
  Result: Base64 string representation
  Example: "/9j/4AAQSkZJRgABAQEAZABkAAD..." (~89,916 chars)
  Purpose: Make binary data safe for MongoDB text storage

  3.5: Detect MIME Type
  ---------------------
  Code: content_type = mimetypes.guess_type(img_path.name)[0]
  Input: "001.jpg"
  Output: "image/jpeg"
  Fallback: "application/octet-stream" if unknown

  3.6: Create MongoDB Document
  ----------------------------
  Code:
    doc = {
        "id": img.get("id"),                    # "001"
        "filename": img.get("filename"),        # "001.jpg"
        "speciality": img.get("speciality"),    # "oncologist"
        "disease_area": img.get("disease_area"), # ["cancer", "tumor"]
        "image_base64": image_b64,              # Base64 string
        "content_type": content_type,           # "image/jpeg"
        "created_at": datetime.utcnow()         # Timestamp
    }

  3.7: Upsert to MongoDB
  ---------------------
  Code: self.collection.update_one(
          {"id": doc["id"]}, 
          {"$set": doc}, 
          upsert=True
        )
  
  Behavior:
  - If document with this "id" exists: UPDATE it
  - If document with this "id" doesn't exist: INSERT it
  - MongoDB automatically adds "_id" field (ObjectId)

Step 4: Seeding Complete
-------------------------
Result:
- 24 images stored in MongoDB (1 missing: 302.png)
- Each document contains full base64 image data
- Each document has MongoDB-generated ObjectId
- Average document size: ~90 KB per image

VERIFICATION:
-------------
After seeding, MongoDB contains:
  Database: epocrates
  Collection: images
  Documents: 24
  Fields per document: 8
    - _id (ObjectId, auto-generated by MongoDB)
    - id (string, custom identifier)
    - filename (string)
    - speciality (string)
    - disease_area (array of strings)
    - image_base64 (string, ~89,916 chars)
    - content_type (string)
    - created_at (datetime)

4. IMAGE FETCHING PROCESS (API Retrieval)
================================================================================

ENDPOINT:
---------
GET /api/images/filter

PURPOSE:
--------
Filter images by speciality and/or disease area, return complete MongoDB
documents including base64 encoded image data and MongoDB ObjectId.

PARAMETERS:
-----------
Query Parameter: speciality (optional, default: "all")
  Values: "all", "oncologist", "general physician", "pediatrician",
          "cardiologist", "dermatologist"

Query Parameter: disease_area (optional, default: "all")
  Values: "all", or any disease name like "cancer", "heart disease", etc.

STEP-BY-STEP PROCESS:
----------------------

Step 1: API Request Received
-----------------------------
Client Request:
  GET http://localhost:8000/api/images/filter?speciality=oncologist&disease_area=cancer

FastAPI Route Handler:
  File: src/api/endpoints/image_search.py
  Function: async def filter_images(speciality, disease_area)

Parameters Extracted:
  speciality = "oncologist"
  disease_area = "cancer"

Step 2: Call ImageService.search_images()
------------------------------------------
Code:
  results = image_service.search_images(
      speciality="oncologist",
      disease_area="cancer"
  )

Step 3: Reload Images from MongoDB
-----------------------------------
Code: self._load_images()

Why: Ensure latest data (in case external changes to MongoDB)

Process:
  3.1: Query MongoDB
  ------------------
  Code: docs = list(self.collection.find({}))
  Result: All documents from MongoDB (full documents, no exclusions)
  Includes: _id, id, filename, speciality, disease_area, 
            image_base64 (~89,916 chars), content_type, created_at

  3.2: Process Each Document
  --------------------------
  For each doc:
    a) Add image_url field:
       doc["image_url"] = f"{self.base_url}/api/images/{doc['id']}"
       Example: "http://localhost:8000/api/images/001"

    b) Convert ObjectId to string:
       if "_id" in doc:
           doc["_id"] = str(doc["_id"])
       Before: ObjectId('694a490ea0323d9d820b8e1a')
       After:  "694a490ea0323d9d820b8e1a"
       Reason: ObjectId not JSON-serializable, needs string conversion

  3.3: Store in Memory
  --------------------
  Code: self.images = docs
  Result: List of 24 complete documents cached in memory

Step 4: Filter Images
---------------------
Code:
  spec = "oncologist".strip().lower()
  disease = "cancer".strip().lower()

For each image in self.images:

  4.1: Check Speciality Match
  ---------------------------
  Condition: spec == "all" OR image.speciality == "oncologist"
  
  Image 001: speciality = "oncologist" → MATCH
  Image 101: speciality = "general physician" → NO MATCH (skip)

  4.2: Check Disease Area Match
  -----------------------------
  Condition: disease == "all" OR "cancer" in image.disease_area

  Image 001: disease_area = ["cancer", "tumor"] → MATCH
  Image 003: disease_area = ["cancer", "diagnostics"] → MATCH
  Image 005: disease_area = ["cancer", "inpatient care"] → MATCH

Step 5: Build Response
----------------------
Matched Images: [001, 003, 005] (3 images)

Response Structure:
{
    "total": 3,
    "results": [
        {
            "_id": "694a490ea0323d9d820b8e1a",
            "id": "001",
            "filename": "001.jpg",
            "speciality": "oncologist",
            "disease_area": ["cancer", "tumor"],
            "image_url": "http://localhost:8000/api/images/001",
            "image_base64": "/9j/4AAQSkZJR...~89,916 chars...",
            "content_type": "image/jpeg",
            "created_at": "2025-12-23T07:47:25.781000"
        },
        ... 2 more complete documents
    ]
}

Step 6: Pydantic Validation
----------------------------
Code:
  return ImageSearchResponse(
      total=results["total"],
      results=results["results"]
  )

Pydantic Schema: ImageSearchResponse
  - total: int
  - results: List[ImageSchema]

Each ImageSchema validates:
  - mongo_id: MongoDB ObjectId (as string)
  - id: Custom image ID
  - filename: Image filename
  - speciality: Medical speciality
  - disease_area: List of diseases
  - image_url: Constructed URL
  - image_base64: Full base64 data
  - content_type: MIME type
  - created_at: Timestamp

Step 7: JSON Serialization
---------------------------
FastAPI automatically converts Pydantic models to JSON

Response Headers:
  HTTP/1.1 200 OK
  Content-Type: application/json
  Content-Length: ~270000 (for 3 images with base64)

Response Body: JSON object with total and results array

Step 8: Client Receives Response
---------------------------------
Client gets complete MongoDB documents including:
  ✓ MongoDB ObjectId (as string)
  ✓ All metadata fields
  ✓ Full base64 encoded image data
  ✓ Constructed image URL
  ✓ MIME type and timestamp

Client can:
  - Display image: decode base64 and render
  - Store locally: save base64 or binary
  - Reference by _id: use MongoDB ObjectId
  - Share URL: use constructed image_url

MONGODB DOCUMENT STRUCTURE:
----------------------------
Database: epocrates
Collection: images

Complete Document Example:
{
  "_id": ObjectId("694a490ea0323d9d820b8e1a"),  ← MongoDB auto-generated
  "id": "001",                                   ← From JSON metadata
  "filename": "001.jpg",                         ← From JSON metadata
  "speciality": "oncologist",                    ← From JSON metadata
  "disease_area": ["cancer", "tumor"],           ← From JSON metadata
  "image_base64": "/9j/4AAQSkZJR...",           ← Encoded from file
  "content_type": "image/jpeg",                  ← Detected from filename
  "created_at": ISODate("2025-12-23T07:47:25Z") ← Generated on insert
}

Field Details:

  _id (ObjectId, 24 hex chars when stringified)
    Purpose: MongoDB primary key
    Generated: Automatically by MongoDB on insert
    Example: "694a490ea0323d9d820b8e1a"
    Usage: Unique document identifier

  id (string)
    Purpose: Custom image identifier
    Source: imglibrary.json
    Example: "001", "102", "305"
    Usage: Human-readable reference

  filename (string)
    Purpose: Original filename
    Source: imglibrary.json
    Example: "001.jpg", "004.png"
    Usage: File reference

  speciality (string)
    Purpose: Medical specialty category
    Source: imglibrary.json
    Values: "oncologist", "general physician", "pediatrician",
            "cardiologist", "dermatologist"
    Usage: Filtering by specialty

  disease_area (array of strings)
    Purpose: Associated diseases/conditions
    Source: imglibrary.json
    Example: ["cancer", "tumor"], ["heart disease", "arrhythmia"]
    Usage: Filtering by disease

  image_base64 (string, ~89,916 chars average)
    Purpose: Base64 encoded image data
    Source: Encoded from image file
    Example: "/9j/4AAQSkZJRgABAQEAZABkAAD..."
    Size: ~66 KB average (40-100 KB range)
    Usage: Store binary image in text format

  content_type (string)
    Purpose: MIME type for image
    Source: Detected from filename extension
    Values: "image/jpeg", "image/png"
    Usage: Content-Type header when serving image

  created_at (datetime)
    Purpose: Document creation timestamp
    Source: Generated on insert (datetime.utcnow())
    Example: "2025-12-23T07:47:25.781000"
    Usage: Track when image was added

7. CODE FLOW STEP-BY-STEP
================================================================================

STARTUP FLOW:
-------------

1. Application Start
   File: src/main.py
   Action: Start FastAPI application
   Command: python src/main.py

2. Import ImageService
   File: src/services/image_service.py

   a) Load imglibrary.json

   a) Query all documents: self.collection.find({})
   b) For each document:
      - Add image_url field
      - Convert ObjectId to string

   Result: 24 complete documents in memory

7. Application Ready
   State:
   - 24 images in MongoDB
   - 24 documents cached in memory
   - API endpoint available

         )

4. Normalize Parameters
   spec = "oncologist".strip().lower()
   disease = "cancer".strip().lower()

5. Reload Images
   Code: self._load_images()
   Result: Fresh data from MongoDB
   Documents: 24 complete docs with base64

6. Filter Loop
   For each image in self.images:
   
   Check speciality:
     - If spec == "all": Continue
     - If image.speciality == "oncologist": Continue
     - Else: Skip this image
   
   Check disease_area:
     - If disease == "all": Include
     - If "cancer" in image.disease_area: Include
     - Else: Skip this image

7. Collect Results
   Matched: [001, 003, 005]
   Total: 3

8. Build Response Dict
   {
     "total": 3,
     "results": [doc_001, doc_003, doc_005]
   }

9. Pydantic Validation
   Convert to ImageSearchResponse
   Validate each ImageSchema

10. JSON Serialization
    FastAPI converts to JSON
    ObjectId already converted to string

11. HTTP Response
    Status: 200 OK
    Content-Type: application/json
    Body: Complete JSON with base64 data

12. Client Receives
    Parse JSON
    Access base64 data
    Display or process images

FILTERING LOGIC DETAIL:
-----------------------

Pseudocode:
```
function matches(image, speciality, disease_area):
    # Check speciality
    if speciality != "all":
        if image.speciality.lower() != speciality.lower():
            return False
    
    # Check disease area
    if disease_area == "all":
        return True
    
    # Check if disease in disease_area array
    for disease in image.disease_area:
        if disease.lower() == disease_area.lower():
            return True
    
    return False
```

SEEDING ERRORS:
---------------

Error: imglibrary.json Not Found
  Trigger: json_path.exists() returns False
  Exception: FileNotFoundError
  Message: "imglibrary.json not found at {path}"
  Impact: Application fails to start
  Solution: Verify file exists at backend/imglibrary.json

Error: imglibrary/ Directory Not Found
  Trigger: images_dir.exists() returns False
  Exception: FileNotFoundError
  Message: "imglibrary directory not found at {path}"
  Impact: Application fails to start
  Solution: Create backend/imglibrary/ folder

Error: Image File Missing
  Trigger: img_path.exists() returns False
  Behavior: Skip this image, continue with others
  Impact: Fewer images in database
  Example: 302.png missing (24 images instead of 25)
  Solution: Add missing files to imglibrary/ folder

Error: JSON Parse Error
  Trigger: Invalid JSON syntax in imglibrary.json
  Exception: json.JSONDecodeError
  Impact: Application fails to start
  Solution: Fix JSON syntax, validate with JSON linter

Error: MongoDB Connection Failed
  Trigger: Cannot connect to MongoDB
  Exception: pymongo.errors.ConnectionFailure
  Message: Varies (network error, auth failure, etc.)
  Impact: Application fails to start
  Solution:
    - Check MongoDB is running
    - Verify connection string
    - Check network connectivity
    - Verify credentials

Error: MongoDB Upsert Failed
  Trigger: Database write error
  Exception: pymongo.errors.PyMongoError
  Impact: Image not saved to database
  Behavior: Error logged, continues with next image
  Solution: Check MongoDB logs, verify permissions

-----------
